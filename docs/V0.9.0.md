# v0.9.0 - presentacion rapida + DOM + CSS lite + JavaScript

## 1. Presentacion (resultado del bench F9)
Medido en la PS4: `Present` solo = 16,7 ms (60 fps); copiar 1920x1080 = 50 ms; copias 1:1 pequenas = 16,7 ms. El coste es rellenar ~2 M pixeles, no presentar.
- **Interfaz con repintado parcial** (`uipart=1`, por defecto): se compara el lienzo con el fotograma anterior y solo se sube/copia el rectangulo que cambio
  (`SDL_UpdateWindowSurfaceRects`); el cursor se restaura/pinta aparte. Cada 3 s se fuerza un fotograma completo por seguridad. Si
  `SDL_UpdateWindowSurfaceRects` falla se desactiva solo. Si ves restos/parpadeos: Configuracion > Interfaz > "no".
- **Video**: `vpart` ahora tambien funciona con raton conectado (el cursor se borra a negro fuera del video). Recomendado: `vscale=1` (1:1, sin escalar).
- Pendiente de medir: el log trae `[perfui]` solo si falla; mide scroll con F9/log.

## 2. DOM + CSS lite (`js=1`) y JavaScript (`js=2`, por defecto)
Flujo: HTML -> `Dom::parse` -> CSS externos (max 5, 400 KB) -> scripts (inline + externos, max 12, 1,5 MB) -> `DOMContentLoaded`/`load` ->
`Dom::serialize` (omite `display:none`/`visibility:hidden`/`hidden`, aplica `color`) -> `parseHtml` de siempre. El maquetador no cambia.
- CSS lite: selectores tag/#id/.clase/[attr]/:not/:first-child/:nth-child y combinadores; `display`, `visibility`, `color`; especificidad, orden y `!important`;
  `@media` se ignora (queda fuera a proposito); pseudoclases dinamicas (:hover...) nunca coinciden.
- JS (QuickJS-ng v0.18.0): `document`, `Element`, `classList`, `style`, `dataset`, `querySelector(All)`, `innerHTML`, `createElement`, eventos
  (`addEventListener`/`dispatchEvent`/`click()`), `setTimeout/Interval`, `requestAnimationFrame`, Promesas, `fetch`/`XMLHttpRequest` (solo GET, max 10 por pagina),
  `localStorage` (en memoria), `URL`, `location`, `navigator`, `console` (va a log.txt como `[js]`).
- Limites: 64 MB, pila 512 KB, 2,5 s por script, 250 ms por temporizador. Un script que falla no para a los demas.
- Los cambios del DOM hechos por timers/promesas vuelven a maquetar la pestana (como mucho cada 120 ms).

## 3. No incluido todavia (siguientes pasos)
- `<canvas>` 2D (`getContext` devuelve `null`): es lo siguiente para juegos HTML5; reutilizara `canvas.h`.
- Modulos ES (`type=module`), clics/teclas de la pagina hacia `addEventListener` (hoy solo los lanza el propio JS), `window.location = ...`, WebGL.
- Mapeo nodo<->linea del maquetador (necesario para eventos de raton reales y para `getBoundingClientRect`).

## 4. Como probar en la PS4
1. Ejecuta el workflow (por defecto `js_engine=true`). Si `logs/js_fallback.txt` existe, el build con QuickJS fallo y el PKG va sin JS: sube `logs/build_js_failed.log`.
2. En el log busca `[jsx] DOM ok, N scripts ...` por pagina y `[js]` para consola/errores.
3. Prueba: una pagina estatica normal (no debe cambiar), una con menus `display:none`, y friv.com/juegos sencillos (veras el error exacto que falte).
4. Configuracion > "Paginas con DOM + CSS + JavaScript": 3 estados para aislar regresiones (no / DOM+CSS / DOM+CSS+JS).

## 5. Descargas (motor por trozos, medidor de red/disco)
Contexto: pensado para archivos pesados por WiFi (pkg, zip). Hoy la descarga era un solo flujo sin reanudar y, si se cortaba, se perdia todo el `.part`.
- **Motor por trozos** (`app/dlengine.cpp`): trozos de 16 MB con `Range`; cada trozo completo se anota en `<archivo>.part.meta`. Si la conexion se corta, un trozo se
  reintenta solo desde el ultimo byte recibido (hasta 6 veces seguidas sin avanzar, espera creciente). Si cancelas o se cierra el navegador, lo descargado se conserva:
  vuelve a abrir el mismo enlace o usa **Descargas > Descargas incompletas > [continuar]**. Servidor sin `Range` (responde 200): flujo unico como antes.
- **Conexiones paralelas** (Configuracion > Descargas, `dlconn`): 1 (por defecto, reanudable), 2, 3, 4, 6 o 0 (= motor antiguo completo, de respaldo). Varias conexiones ayudan
  con servidores que limitan por conexion (p. ej. archive.org); en WiFi demasiadas pueden empeorar: por eso el medidor.
  Aviso: usa libSceHttp desde varios hilos a la vez (cada hilo con su propia conexion); en la consola no esta probado. Por eso el valor por defecto es 1.
- **Disco**: reserva el tamano final al empezar, escritura en bloques de 2 MB por hilo y buffer de 1 MB; cada trozo se anota solo cuando ya esta vaciado a disco.
- **Medidor** (`about:dlbench`, Configuracion > "Medir descargas"): red con 1, 2 y 4 conexiones (8 s cada una, sin guardar) + disco (64 MB secuencial y en 4 flujos
  intercalados). Muestra MB/s medio y min/max por segundo, reintentos, recomendacion de conexiones y [Usar N conexiones]. Servidores de prueba: tres publicos (Hetzner,
  thinkbroadband, OVH: **no verificados desde aqui**) o la ultima URL que descargaste. Cancelar: boton O. Log: lineas `[dlbench]`, `[dleng]`, `[dl] motor`.
- Pruebas en el PC (`tools/tests/test_dlengine.cpp`, con ASan/UBSan y TSan): descarga limpia 1/3/6 conexiones, cortes de red, servidor sin Range, cancelar y reanudar,
  reanudar contra un servidor que ya no admite Range, 404, pagina HTML en vez del archivo, reintentos agotados, modo medidor y archivo menor que un trozo.
- No incluido: instalar el PKG desde el navegador (hoy se guarda en `/data/psbrowser/downloads/`), descomprimir ZIP en la consola, SHA-256, cola de varias descargas.
